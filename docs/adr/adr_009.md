# ADR-009 — Implantação híbrida enxuta na Azure para validação Mobile First

**Estado:** PROPOSTO (autor: Caio Soares de Andrade — R6/R7; pendente de validação por R2 e R3)

## Contexto

O Challenge 2 Berkanan tem como público-alvo consumidores brasileiros utilizando navegadores móveis em supermercados (redes 4G/5G), com avaliação presencial/remota com usuários prevista para **30/11–02/12/2026** (issue #34) e meta de latência mediana **≤ 10 s** (ADR-008 e métricas do projeto).

Três restrições técnicas guiam a implantação em nuvem:

1. **Obrigatoriedade de HTTPS para câmera mobile:** navegadores Android/iOS bloqueiam `navigator.mediaDevices.getUserMedia()` em origens HTTP inseguras (exceto `localhost`).
2. **Persistência do ChromaDB 0.5.20:** o ChromaDB utiliza SQLite internamente; compartilhamentos de rede SMB (como Azure Files em serviços PaaS sem disco local dedicado) apresentam risco conhecido de bloqueio (`database is locked`) e corrupção em escrita concorrente.
3. **Infraestrutura enxuta e baixo atrito operacional:** o ADR-008 proíbe Prometheus e o prazo até a entrega final (**07/12/2026**) exige aproveitar diretamente o `compose.yaml`, as migrações SQL (`migrations/001`–`011`) e o script de ingestão (`scripts/ingest_chroma.py`) já prontos no repositório, sem introduzir Kubernetes (AKS) ou serviços não aprovados.

## Decisão proposta

Adotar uma **topologia híbrida enxuta na Microsoft Azure**, com região principal **`brazilsouth`** (menor latência para usuários e redes 4G no Brasil):

1. **Camada de API e Dados (`infra/azure/compose.prod.yaml`):**
   - **VM Linux Ubuntu 24.04 LTS (`Standard_B2ms` — 2 vCPU, 8 GB RAM, disco Premium SSD local)** executando Docker Compose com os quatro serviços:
     - `caddy` (`caddy:2.8.4-alpine`): proxy reverso nas portas `80`/`443` com **HTTPS automático via Let's Encrypt**, cabeçalhos de segurança HTTP, CORS restrito à origem do frontend e limite de corpo na borda (`CADDY_MAX_BODY_SIZE=512KB`) para proteger memória contra fotos brutas (ADR-002).
     - `backend` (FastAPI + LangGraph): exposto apenas na rede Docker interna (`expose: 8000`), sem porta pública direta.
     - `postgres` (`postgres:16.4-alpine`): persistência em volume SSD local (`postgres_data`), sem exposição de porta externa (`5432` bloqueada no NSG).
     - `chromadb` (`chromadb/chroma:0.5.20`): persistência em volume SSD local (`chroma_data`), evitando incompatibilidades de lock SQLite em SMB, sem exposição externa (`8001` bloqueada no NSG).
2. **Camada Web Mobile First (`frontend/` quando entregue por R5):**
   - **Azure Static Web Apps (`Free` tier)** com CDN e TLS nativos, configurado via `infra/azure/staticwebapp.config.json`, comunicando-se via HTTPS com o domínio da API na VM (`CORS_ALLOWED_ORIGIN`). Alternativamente, caso o time prefira entrega única antes do prazo final, o frontend estático também pode ser servido diretamente pelo Caddy na mesma VM.
3. **Bootstrap idempotente e Entrega Contínua controlada:**
   - Script `infra/azure/bootstrap_stack.sh` aplica migrações pendentes via `migrations/migrate.sh` (`SEED=0`), verifica/indexa a coleção do ChromaDB via `scripts/ingest_chroma.py`, sobe os containers e valida `GET /health`.
   - Workflow `.github/workflows/deploy-azure.yml` acionado manualmente (`workflow_dispatch`, com GitHub Environment `azure-staging`), executando pré-validação obrigatória (baseline, testes unitários e `check_compose.sh`), deploy via SSH e **rollback automático para o commit anterior** em caso de falha.

## Segurança e LGPD

- Portas internas (`5432`, `8000`, `8001`) permanecem bloqueadas no Network Security Group (`infra/azure/provision_azure_cli.sh`).
- Segredos (`POSTGRES_PASSWORD`, `GEMINI_API_KEY`, `FALLBACK_API_KEY`) residem apenas em `infra/azure/.env.prod` na VM (nunca versionado) e nos GitHub Environment Secrets.
- O proxy Caddy e o backend não devem registrar imagens (`image_base64`) nem dados pessoais de saúde nos logs ou em `metricas_requisicao` (ADR-008).

## Consequências

- **Positivas:** reaproveita 100% dos artefatos Docker/SQL/RAG já validados localmente; elimina *cold start* na API e no modelo de embeddings multilíngue; garante HTTPS válido no celular em minutos; mantém custo previsível e rollback simples por commit Git.
- **Negativas / Trade-offs:** exige cuidados básicos de VM única (backup periódico de `postgres_data`, disco SSD monitorado e restrição de SSH via `ADMIN_CIDR`), aceitáveis para uma PoC acadêmica com entrega em 07/12/2026.
